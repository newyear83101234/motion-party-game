## 1. 共通原則

1. **Lv1＝現在的玩法（幾乎不動）**，拿 3 星就開下一級；越後面越難。舊測試大多不用改、新手不會被嚇跑。
2. **每一級都要有「看得見的新東西」**（例：「魚會游了！」），解鎖畫面直接秀出來。
3. **金星沙漏**（Lv3 起）：固定位置一顆金星慢慢被沙蓋住。沙漏跑完前第一次就答對＝金星；跑完還是可以答（變銀星），**題目照常繼續、不算錯、不扣東西**。不用數字、不用紅色、不閃、沒有滴答聲；最後 3 秒星星轉銀色。聽音題：語音播完才開始算；按 🔊 重聽時沙漏暫停；跑完後 0.3 秒內點對仍算金星（寬限）。暫停選單要凍結（走主程式遊戲時鐘 gLater／gNow）。
4. **等級徽章不用星星圖案**（會跟分數混淆）：Lv1 綠、Lv2 藍、Lv3 紫、Lv4 橘、Lv5 金，圓形徽章＋數字。
5. **聽音題的干擾項不用 ㄣ/ㄥ、ㄢ/ㄤ、ㄓ/ㄗ、ㄕ/ㄙ、ㄔ/ㄘ 這幾組差別**（台灣口音與合成語音常聽不出，只能亂猜）；這幾組只用在看注音題（點餐、尋寶、積木）。每題最多 1 個「只差聲調」的假選項；三聲變調、輕聲的排除規則（zhuyin.js `toneVariant`）套用到所有新干擾。
6. 舊存檔照顧：某遊戲原本 `best` 已是 3 星 → 直接開到 Lv2。

## 2. 主程式 7 個遊戲＋翻牌：等級 Lv1–Lv5（js/zhuyin.js）

### 2.1 存檔與流程
- `zy{n}_lv` ＝ `{ 模式: { max: 1..5 已開到第幾級, cur: 上次選的級, st: { "1": 最佳星數, ... }, two: 在 max 級連續拿 2 星的次數 } }`；進備份碼（ZY2 帶 `lv`，清洗夾 1..5）。`save.best[模式]` 保留（＝各級最高星數），舊畫面照用。
- 介紹卡（showPick）：名稱下面一排五色等級徽章（沒開的灰＋🔒），預設選 **max**；每顆下面小字＝那級最佳星數。點徽章切換。
- 升級：在 max 級拿 3 星 → max+1；或在 max 級**連續 3 次 2 星** → max+1（防卡死）。在 max 級連 2 次 1 星 → 貓頭鷹問要不要回上一級暖身（不強迫）。
- 解鎖畫面：「🎉 第 N 級打開了！」＋一行新東西說明（例「魚會游了！」）＋一句配音。
- 防刷星：玩「比 max 低 2 級以上」＝暖身，結算最多放 1 顆星進星星罐（best 照記；是少拿不是扣）。
- 高等級獎勵：3 星時多放星星罐 Lv3–4 +1、Lv5 +2。
- 作答時間紀錄：每模式記最近 30 次「第一次就答對」的秒數（每音節正規化），存 `zy{n}_rt`。累積 ≥15 筆後，沙漏秒數＝`clamp(中位數×倍率, 下限, 預設×1.5)`，倍率 Lv3 2.0／Lv4 1.6／Lv5 1.3；不到 15 筆用預設秒數。

### 2.2 星星
金星＝第一次就答對、而且在沙漏內（沒有沙漏的級＝第一次就對）。
| 級 | 3 星 | 2 星 | 其他 |
|---|---|---|---|
| Lv1 | 金 ≥ n−1（現狀）| 金 ≥ ⌈n/2⌉ | 現狀 tolerate |
| Lv2、Lv3 | 金 ≥ n−1 | 金 ≥ ⌈n/2⌉ | |
| Lv4 | 金 ≥ n−1 | 金 ≥ ⌈n/2⌉ | 積木／蛙／地鼠 tolerate 改 0（錯 1 次就不算金）|
| Lv5 | 全金 | 金 ≥ n−2 | 同 Lv4 |

### 2.3 各遊戲旋鈕（Lv1 → Lv5；Lv1＝現狀）
- **釣魚**：魚 4/4/5/6/6 條；干擾 全不同→同聲母或同韻母→再加 1 個只差聲調→全近似→全近似＋聲調；Lv3 起魚慢慢游、Lv4–5 游快一點；Lv5 題目圖藏起來只靠耳朵。沙漏 Lv3/4/5：單音節 12/9.5/7 秒，每多 1 音節 +2 秒。
- **點餐**：貨架 4/5/6/6/8 樣；近音食物 0/1/2/3/全部；Lv4 起客人一次點 2 樣（兩個注音泡泡，都拿對才算完成；任一個第一次就對才算金…實作可簡化為兩樣都第一次就對＝金）。沙漏同釣魚＋3 秒。
- **積木**：多餘積木 2/3/4/5/6 顆；Lv3 起多餘積木改放易混符號（ㄅㄆ ㄉㄊ ㄢㄤ ㄣㄥ ㄓㄗ ㄕㄙ ㄧㄩ ㄛㄜ）；Lv4 起出現 3 音節詞、tolerate 0。沙漏＝要放的積木數 × 4/3.2/2.5 秒。
- **尋寶**：物件 8/8/10/12/12；場景內近音物件 0/1/2/3/3；顏色短語題比例 0/0/⅓/½/½。沙漏單音節 15/12.5/10 秒＋每多 1 音節 2 秒。
- **翻牌**：4/6/8/10/12 對；開局全部亮著預覽 3/2/1/0/0 秒；Lv4 起混入 2 對同聲母的詞；3 星錯配上限＝對數 × 1.25/1.1/0.9/0.75/0.6（取整），2 星＝×2。原本 8/16/24 張選擇改由等級取代。不計時。
- **聲調氣球**：Lv1 單音節、氣球不動；Lv2 單音節加輕聲選項（5 顆）；Lv3 雙音節只改 1 個字、氣球慢飄（飄出頂端從底部再冒，不算錯）；Lv4 飄快一點；Lv5 兩個字都可能改、飄得快。沙漏同釣魚。
- **打地鼠**：同時冒出 2/2/3/3/3 隻；正解出現率 45/40/35/30/30%；每個目標要敲中 3/3/4/4/5 次；Lv4 起 tolerate 0。不另計時（沿用自適應探頭，下限不變）。
- **跳跳蛙**：每排荷葉 2/3/3/4/4 片（Lv1 第一題 2 片、之後 3 片＝現狀）；Lv3 起順序陷阱；Lv4 起 3 音節詞、tolerate 0。沙漏每排 6/4.8/3.5 秒。

### 2.4 給爬塔用的介面（js/zhuyin.js 實作，爬塔模組呼叫）
```
playFloor(opts) → { done: Promise<Result>, abort() }
opts = {
  mode: "fish"|"order"|"build"|"hunt"|"tone"|"whack"|"frog",
  n: 題數,
  lv: 1..5（套 §2.3 的參數）,
  timer: "off" | "silver" | "heart",   // off＝不出沙漏；silver＝沙漏跑完只變銀；heart＝沙漏跑完發 {type:"timeout"}（爬塔扣心），題目繼續、沙漏消失
  extra: { flash?: bool,   // 點餐／尋寶：注音亮 2 秒後蓋起來（點蓋子不會再打開；要靠記憶）
           noPic?: bool,   // 聽音題：題目圖藏起來
           words?: [詞物件] // 指定題目（例：第 100 層用「登頂」）
         },
  onEvent: ev => {}        // ev.type："gold" | "silver" | "wrong" | "timeout"；ev.q＝第幾題
}
Result = { golds, silvers, wrongs, timeouts, aborted }
```
- 爬塔局：不跑「再試一次」、不出一般結算、不給貼紙、不進星星罐、不記 best／lv／stats（獎勵由爬塔模組自己給）。
- 進入時自己把該模式的遊戲畫面開起來；結束（或 abort）時把遊戲畫面收掉，回到呼叫前的畫面（爬塔畫面在上面蓋著）。
- 🏠 暫停選單在爬塔局顯示「繼續／離開挑戰」；離開＝abort（Result.aborted=true）。

## 3. 泡泡救援灣（js/zhuyin-bubble.js）— 小孩最喜歡，加最多

- **新增第 4 區（第 31–40 關，ㄐㄑㄒ）與第 5 區（第 41–50 關，ㄓㄔㄕㄖ）**，通過第 30 關才開。新機制：**天花板下壓**——每 N 發整片往下降一排（第 4 區 N＝8→7，第 5 區 7→6），泡泡碰到底線＝這關重來（跟現在滿盤一樣溫和）。第 5 區另加**石頭泡泡**（不能被同色消掉，只能靠「跟天花板斷開」掉下來）。救的動物用現有寵物圖（IMAGE/zhuyin/pets/），每區一種。
- 標準桿照現有方式用求解器驗證（tools/zy-test/bubble.js 擴充：求解器要模擬天花板下壓與石頭）。
- 給爬塔的 Boss 介面（zhuyin.js 泡泡區段實作）：
```
playBubbleBoss({ level: 第幾關的盤面(0 起), ceilingEvery: N, onEvent }) → { done: Promise<{ cleared, shots, presses, aborted }>, abort() }
```
  Boss 模式：天花板每 N 發下壓；碰到底線**不重來**，改發 `onEvent({type:"press"})`（爬塔扣 1 心）並把整片往上退 2 排；救完動物＝cleared。不存泡泡進度、不給星星。

## 5. 爬塔（無限挑戰）：「挑戰燈塔」

### 5.1 入口
- 主島燈塔岬的燈塔＝「挑戰燈塔」🗼（GAME_INFO.tower，貼紙 30 張解鎖）；燈塔上加浮標，點了走介紹卡；🗺️ 全部遊戲清單也列在主島。

### 5.2 代號（24 個）
生肖：🐭鼠 🐮牛 🐯虎 🐰兔 🐲龍 🐍蛇 🐴馬 🐑羊 🐵猴 🐔雞 🐶狗 🐷豬；星座：♈牡羊座 ♉金牛座 ♊雙子座 ♋巨蟹座 ♌獅子座 ♍處女座 ♎天秤座 ♏天蠍座 ♐射手座 ♑摩羯座 ♒水瓶座 ♓雙魚座。
- 選代號／放棄代號在**家長閘門後面**（沿用現有家長區閘門）；家長頁用白話寫清楚送出什麼（代號、最高樓層；不送名字）。

### 5.3 一場挑戰的規則
- 10 段 × 10 層。打過第 10、20…層（Boss）＝存檔點，下次從下一層開始。
- 一層只玩一種遊戲（7 種短題輪替：釣魚／點餐／積木／尋寶／氣球／地鼠／蛙；同段內各至少一次、不連續重複；依樓層編號固定排，不是每次隨機）。1–30 層每層 3 題，31 層起 4 題，91 層起 5 題。
- 愛心 3 顆。答錯扣 1 顆（題目繼續，不揭曉答案）；超時依該段規則；第 5、15、25…層各補 1 顆（上限 3）；打過 Boss 補滿。愛心用完＝這場結束。
- 每段第 1 層（11、21…）＝教學層：不扣心，貓頭鷹先講這段的新東西。
- 保底：同一段連輸 3 場 → 下一場多 1 顆金色愛心；連輸 5 場 → 多 2 顆（小孩只看到「貓頭鷹送你一顆愛心」）。
- 打過 Boss 問「繼續爬／休息一下」。

| 層 | 參數 | 新東西 |
|---|---|---|
| 1–10 | Lv1、不計時 | — |
| 11–20 | Lv2、不計時 | 干擾變像 |
| 21–30 | Lv3、沙漏（超時只變銀，不扣心） | 金星沙漏 |
| 31–40 | Lv3、沙漏超時扣心、每層 4 題 | 超時會掉心 |
| 41–50 | Lv4（東西會動） | 魚游、氣球飄 |
| 51–60 | Lv4＋flash（點餐／尋寶注音亮 2 秒蓋起來） | 記憶 |
| 61–70 | Lv5 | 最難參數 |
| 71–80 | Lv5＋flash | |
| 81–90 | Lv5＋flash＋noPic（聽音題藏圖） | 只靠耳朵 |
| 91–100 | Lv5＋全部、每層 5 題 | |

- Boss：10/30/50/70/90＝**泡泡 Boss**（playBubbleBoss，下壓 8/8/7/7/6 發，盤面挑現有關卡由易到難）；20/40/60/80＝**6 題連戰**（每題換一種遊戲、超時扣心、參數用該段）；100＝連戰 6 題 → 泡泡 Boss（6 發）→ 用積木拼出「登頂」。

### 5.4 失敗與結算（不能讓小孩哭）
- 不出現 GAME OVER：最後一顆心掉時，角色撐降落傘飄回存檔點；貓頭鷹「這座塔今天好滑喔！」（怪塔不怪人）。
- 掉心：愛心變泡泡飄走、軟音效；不碎、不紅閃、不震畫面。
- 結算＝一座塔：這次的旗子插在第 N 層、上次的半透明旗子，顯示「比上次高 X 層！」與「再 Y 層就到 Boss」。「再爬一次」大、「去玩別的」小；連輸 2 場建議先去泡泡灣玩一關。

### 5.5 獎勵（只獎勵第一次，不洗爆經濟）
- 第一次到達每個 5 的倍數層 +1 星（共 20 星）；第一次打倒每個 Boss +1 枚扭蛋幣＋塔徽章（共 10 枚）；登頂＝王冠徽章＋排行榜王冠。每場保底 1 星（一天最多 3 場有）。

### 5.6 後端（擴充同樂廣場 Apps Script，clasp 部署、網址不變）
- 新分頁「爬塔」固定 24 列：代號、秘密碼雜湊、最高樓層、名次序號（新紀錄的先後，取代日期）、到期日（只到日）。**不存每日登入日、不存暱稱、不存 IP**。
- 秘密碼：前端 `crypto.getRandomValues` 128-bit，只存本機（每存檔位一個）；用 **POST** 送；後端存 `SHA-256("zy-tower:" + 秘密碼)`。
- action（POST，text/plain JSON，同現有）：`tw_claim {c,s}`（空的或過期→給你；同一人→ok；別人→taken）、`tw_ping {c,s}`（延長到期；過期或被拿走→expired/lost）、`tw_score {c,s,f}`（f 只能 1..100、比原本最多 +20）、`tw_leave {c,s}`（清整列）。
- 到期＝最後活動日＋7 天；惰性判斷（claim／ping／score／讀榜時順便清）；過期清整列（含雜湊）。
- doGet 多回 `tower: { board: [{c, f}] 前 5 名（f>0，同層看序號）, taken: [代號] }`。
- 共用全站每分鐘上限、暫停開關、LockService。
- 前端：分數離線排隊重送；代號被收回時通知小孩重新選、本機樓層歸零（徽章保留）。

## 6. 配音：要不要每次都重錄？（阿葉的疑問）

**結論：原本的做法就對，只是收尾要再自動一點。不需要每次重錄，也不建議改成「遊戲當下才合成」。**

事實（10-13 盤點）：
- 現在就是「只錄新的／改過的句子」，不是整套重錄。688 句累計成本約 **US$1.7**（大部分花在自動盲聽檢查，不是生成）；補錄 1 句（「積木！」）約 3 分鐘。
- 每次更新真正麻煩的不是錄音，是三件「人工記得做」的事：①改了舊台詞的字要手動從 progress.json 刪編號，不然會唸舊的（踩過）②版號連鎖：manifest 日期 → voice.js → zhuyin.js → html ③要記得跑。
- 沒錄到的句子不會壞：自動退回平板內建語音（聲音不同但會唸）。
